# Documentation Rules

Documentation should explain decisions, not obvious syntax.

Document:

- architecture decisions
- external integrations
- authentication flows
- database design
- environment variables
- deployment requirements
- complex business rules

Avoid documenting trivial implementation details.

---

## API Documentation

Document:

- endpoint
- method
- authentication
- parameters
- request body
- response
- errors
- examples

---

## README

Every project should explain:

1. What the project does.
2. Technology stack.
3. Installation.
4. Environment variables.
5. Development commands.
6. Testing.
7. Deployment.
8. Architecture overview.
